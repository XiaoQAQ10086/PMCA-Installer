# 图形界面（M11）实现说明

> 最后更新：2026-09-28
> 状态：✅ **已完成并在真机上跑通**

## 一、做成了什么

一个**中文的、单文件的、双击就能用**的窗口程序：

```
D:\Sonny\dist\索尼相机应用安装器.exe        4.42 MB   ← 用户用的就是这个
D:\Sonny\dist\sony-diag.exe                 0.86 MB   ← 排查问题用的命令行工具
```

界面从上到下四块：

| 区块 | 内容 |
|---|---|
| **① 相机** | 自动检测，显示型号 / 序列号 / 当前模式，有个状态色圆点，右边"重新检测" |
| **② 应用包** | 显示已选文件名、大小、完整路径，右边"选择文件…" / "换一个" |
| **③ 安装** | 大按钮 + 进度条 + 状态文字；成功/失败都有对应的提示条 |
| **④ 运行日志** | 安装过程每一步都记下来，带颜色分级（正常/成功/警告/错误），可"清空" |

**用户需要做的事**：插上相机 → 选一个 APK → 点"开始安装"。就这些。

相机模式是**全自动**切换的，用户不需要去相机菜单里翻任何设置。

## 二、两个关键技术决定

### 决定 1：渲染用纯 CPU（tiny-skia），不用显卡（wgpu）

iced 默认会启用 `wgpu`（显卡渲染），但还会顺带拉进一堆 Linux 用的东西
（x11、wayland、linux-theme-detection）。

我们关掉默认特性，只启用 Windows 上真正需要的：

```toml
iced = { version = "0.14", default-features = false, features = [
    "tiny-skia",   # 纯 CPU 渲染
    "crisp",       # 像素对齐，文字更锐利
    "web-colors",  # sRGB 颜色处理
    "smol",        # 最轻的异步执行器（iced 必须要一个）
] }
```

**好处**：
- 不需要显卡驱动配合 → 老机器、虚拟机、远程桌面里都能开
- exe 小得多（4.42 MB，用 wgpu 会大好几倍）
- 启动快

**代价**：窗口重绘走 CPU。对这么一个静态小窗口完全够用
（iced 只在有变化时重绘，不是每帧都画）。

### 决定 2：中文字体从系统加载，不内嵌

Windows 自带的中文字体都很大：

| 字体 | 大小 |
|---|---|
| msyh.ttc（微软雅黑） | 18.8 MB |
| simsun.ttc（宋体） | 17.2 MB |
| Deng.ttf（等线） | 15.6 MB |
| simhei.ttf（黑体） | 9.3 MB |

内嵌任何一个，exe 都会从 4.42 MB 膨胀到 15–25 MB，启动也变慢 ——
和"体积小、启动快"直接冲突。

**只内嵌界面用到的那些字**也不行：用户选的 APK 文件名可能是任意中文
（甚至生僻字），子集化之后那些字会变成方框。

**做法**：启动时按优先级从系统读一个：

```
msyh.ttc（微软雅黑） → Deng.ttf（等线） → simhei.ttf（黑体） → simsun.ttc（宋体）
```

Windows 10/11 各版本都自带微软雅黑，所以这条路很稳。
万一一个都没有，界面照样能开，只是中文会显示成方框，并且**在界面上和日志里
都会明确提示**（而不是让用户对着一堆方框发呆）。

## 三、架构：为什么界面不会卡死

相机通信又慢又可能失败：切模式要等相机重新枚举（几秒），
安装要等相机下载整个应用包（几十秒）。这些如果跑在界面线程上，窗口会**直接卡死**。

所以界面**完全不碰相机**，全部丢给后台线程：

```text
   界面线程                          工作线程
      │                                 │
      │  spawn_install(apk)             │
      ├───────── 建通道 ───────────────►│
      │                                 │  跑安装流程
      │  ◄──── WorkerMsg::Step ─────────┤  （每有进展就发一条）
      │  ◄──── WorkerMsg::Progress ─────┤
      │  ◄──── WorkerMsg::Finished ─────┤
      │                                 │
   每 100 毫秒用 try_recv 取一次消息，不阻塞
```

用**定时轮询**而不是 iced 的 `Task::perform`，是因为轮询最简单、最不容易出错：
界面永远不会被后台卡住，消息晚几十毫秒到也无所谓。

另外用 `catch_unwind` 兜底：底层是 COM 和 USB，万一哪儿 panic 了，
界面必须给用户一句明确的话，而不是永远停在"正在安装…"转圈。

## 四、目录结构

```
crates/
  sony-core/     协议栈（代理消息、手写 TLS 1.0、SPK、XPD、HTTP、假商店）
  sony-usb/      Windows WPD 传输层（C 薄封装调 COM）
  sony-install/  ★ 安装编排：命令行和界面**共用这一份**
  app/           命令行诊断工具（bin: app）
  sony-gui/      图形界面（bin: sony-app-installer）
    src/main.rs    入口、窗口设置、字体加载
    src/app.rs     状态机 + 视图
    src/theme.rs   Fluent 配色与控件样式
    src/fonts.rs   系统中文字体查找
    src/worker.rs  后台线程与消息通道
```

### 为什么要有 `sony-install` 这一层

一开始安装逻辑写在命令行里。做界面时如果直接抄一份，就会出现
"命令行能装、界面装不了"这种两边跑偏的情况 —— 而且很难查。

所以把编排抽成独立一层，**两边调用同一个函数**：

```rust
sony_install::install(&apk, &app_name, &mut |事件| { ... })
```

命令行把事件打印出来，界面把事件变成界面文字。逻辑只有一份。

## 五、踩到的坑

### 坑 1：iced 的闭包必须写清参数类型

```rust
.theme(|_: &App| theme::theme())     // ✅ 必须写 `|_: &App|`
.theme(|_| theme::theme())           // ❌ 编译报错
```

只写 `|_|` 的话，Rust 会把生命周期推断成某一个具体的，
而 iced 要求"对任意生命周期都成立"，于是报：

```
implementation of `FnOnce` is not general enough
note: closure with signature `fn(&'2 App) -> Theme` must implement
      `FnOnce<(&'1 App,)>`, for any lifetime `'1`
```

报错信息在几十行之外，第一次看完全不知道在说哪儿。

### 坑 2：iced 必须要一个异步执行器

只写 `tiny-skia` 会报 `No futures executor has been enabled!`，
得再启用 `smol`（或 `tokio`）。选 `smol` 是因为它更小。

### 坑 3：原生"打开文件"对话框不能直接在界面线程里调

Windows 的 `IFileOpenDialog` 是阻塞式的，直接在界面线程调用会让窗口停止重绘
（看起来像卡死）。所以对话框也跑在后台线程上，选完通过通道送回界面。

### 坑 4：新建 crate 后必须加进工作区

`crates/sony-gui/Cargo.toml` 写好了但没加进根 `Cargo.toml` 的 `members`，
cargo 完全看不到它，编译时一片"找不到模块"。

### 坑 5：相机刚切完模式不能立刻开会话

真机上实测：相机切到应用安装模式后会**重新枚举 USB 设备**，
这时候立刻去打开会话，会拿到：

```
0x8007001F: 连到系统上的设备没有发挥作用。
```

这不是真故障，等几百毫秒再来一次就好。

**修法**：切模式确认成功后再多等 600 毫秒，并且"打开 + 握手"最多重试 6 次
（每次间隔 700 毫秒）。加上之后就没再出现过。

### 坑 6：`CloseSession` 不能"顺手"加

我在读相机信息的函数里"顺手"补了一句 `CloseSession`，想着有开有关更规范。
结果后面代理消息握手**稳定报错**：

```
0x8007001F: 连到系统上的设备没有发挥作用。
```

两个原因，都指向"别多此一举"：

1. MTP 的 `CloseSession` 需要**带会话号作为参数**，我传的是空参数 —— 请求是畸形的
2. 设备对象析构时本来就会收尾，显式关会话反而把相机留在中间状态

去掉这一句就好了。原项目（以及我们验证过能跑通的路径）都是**不关**的。

> **教训**：协议里"看起来更规范"的额外操作，如果没有依据，就不要加。
> 这类错误的现象（握手失败）离原因（一句多余的关闭命令）非常远。

### 坑 7（教训，不是代码坑）：别用"按行号裁剪文件"的方式改代码

我在用脚本改代码时，用 `IndexOf("#[cfg(test)]")` 找插入点，结果它匹配到了
**我刚刚插进去的那一行**，导致文件从那里被截断，一次丢掉了 540 行。

当时的处境很被动：项目**没有版本管理**，没有备份，只能凭记忆重写。

**做完两件事之后才恢复**：
1. 立刻 `git init` 并提交（45 个文件纳入版本管理）
2. 改代码一律用编辑工具做**精确文本替换**，不再按行号裁剪

> **教训**：动手改之前先有版本管理。这次的代价是重写一个文件，
> 下次可能是整个项目。

## 五之二、界面路径的真机验证

界面代码最麻烦的是"点一下试试"这种验证方式：自动化点击不可靠
（窗口焦点会被别的程序抢走），人点又只能点正常路径。

所以把 `sony-gui` 拆成了 **lib + bin**：`main.rs` 只负责开窗口，
状态机、后台线程、样式都在 lib 里。这样集成测试可以直接驱动它们。

`crates/sony-gui/tests/real_install.rs` 里的 `gui_install_flow_end_to_end`
走的和真实点击**完全同一条路**：

```text
  set_initial_apk()   ← 相当于"选好了 APK"
  Message::Start      ← 相当于"点了开始安装"
       │
       └─► begin_install() → spawn_install()  ← 真的起后台线程
                 │
                 └─► Message::Tick 轮询 → on_worker() → 状态机
```

只有"Windows 把鼠标点击投递给窗口"这一段没覆盖 ——
那是 iced 框架的事，不是我们的逻辑。

**真机实测通过**（相机 ILCE-6300）：

```bash
set SONY_TEST_APK=某个应用.apk
cargo test -p sony-gui --test real_install -- --ignored --nocapture
```

输出：

```text
正在安装…
Uploading（0%）   →  Uploading（100%）      相机上传设备信息
Downloading（88%）→  Downloading（100%）   相机下载应用包
Installing（0%）  →  Installing（100%）     相机安装
Uploading（0%）   →  Uploading（100%）      相机汇报结果
安装完成
✅ 安装完成：相机已报告成功
相机信息：型号 ILCE-6300，固件 2.01，已安装 20 个应用
✅ 界面这条路径安装成功，进度 100%
```

## 六、测试覆盖

界面部分有 11 个测试，重点覆盖**状态机**（真机上出问题最多的地方）：

| 测试 | 验证什么 |
|---|---|
| `progress_moves_preparing_to_installing` | 第一次进度汇报把状态从"准备"推进到"安装中" |
| `success_ends_in_done` | 成功后进入完成态、进度 100% |
| `failure_keeps_only_first_line_in_status` | 失败时状态行只取第一行（完整信息在日志里） |
| `camera_found_and_missing_update_state` | 找到/没找到相机的状态转换 |
| `step_messages_do_not_advance_stage` | 说明性文字**不会**把状态误推进到"安装中" |
| `cannot_start_without_an_apk` | 没选文件时不能开始，也不会起后台线程 |
| `log_is_capped` | 日志有行数上限，且保留的是**最新**的 |
| `clear_log_keeps_a_marker_line` | 清空日志后留一条说明 |
| `human_size_reads_naturally` | 文件大小显示（字节/KB/MB） |
| `first_line_stops_at_newline` | 多行文本取第一行 |
| `summarize_picks_key_fields` | 相机回报的 JSON 摘要，非 JSON 不 panic |

全项目测试合计 **147 个通过**。

## 七、怎么自己构建

```bash
cd /d D:\Sonny\sony-app-installer

# 开发时运行（窗口会弹出来）
cargo run -p sony-gui

# 出发布版
cargo build --release -p sony-gui
# 产物：target\release\sony-app-installer.exe

# 跑测试
cargo test

# 检查代码质量
cargo clippy --all-targets
```

第一次构建要编译 iced 及其依赖，比较慢（几分钟）；
之后的增量构建只要几秒。
